PROJECT NOTES / LEARNING EXERCISE

A* in ROS 2.

Getting from a map to a path I can see.

Graph search is familiar on paper. Robots made it more concrete: there are maps, coordinate frames, messages, and tools that have to agree before any path can be visualized.

What I've set up

On Ubuntu with ROS 2 Jazzy, I built an A* package in an existing repository, ran the node, and checked its tests. I also configured a small example occupancy grid through map_server and viewed it with RViz.

What I'm working through

The next step is tracing the complete route from a map and a goal to an actual published path, then rendering it clearly. That includes understanding the relevant ROS topics, message types, coordinate frames, and lifecycle behavior.

Why it's here

This isn't a finished robotics application. It's a documented learning exercise in a collaborative codebase, and a reminder that even a familiar algorithm becomes a different problem when placed into a real system.
