PROJECT NOTES / WORKING PROTOTYPE

AtlasLLM.

A document question-answering system, built locally.

The question I started with was simple: what needs to happen between uploading a document and getting an answer that actually uses it?

What I built

The prototype ingests document text, splits it into chunks, creates vector embeddings, stores them in Chroma, retrieves relevant passages, and passes context to a model running locally through Ollama. A simple CLI ties it together.

I also tried separating everyday chat from document questions with intent routing, and rewriting ambiguous queries before retrieval. Those additions exposed the trade-off between adding intelligence to the pipeline and keeping it simple and fast.

Engineering questions

  • How big should a document chunk be before retrieval gets noisy?
  • How can I tell whether a retrieved passage is actually relevant?
  • When does an additional planning or rewriting step help enough to justify the latency?
  • What should the system do when the documents don't contain the answer?

What it taught me

Connecting a model to a vector database is straightforward; making the overall experience accurate, fast, and inspectable is the interesting part. It's a learning project, not a claim of production-scale reliability.
